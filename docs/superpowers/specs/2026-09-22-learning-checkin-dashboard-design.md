# 学习打卡数据看板设计规格

## 1 项目目标

本项目面向计算机专业大一学生，构建一个可在浏览器直接运行的学习打卡数据应用。系统通过每日打卡采集个人学习记录，自动完成持久化、统计、排名、图表展示和文字报告生成，形成“输入数据、保存数据、处理数据、展示数据”的完整闭环。

最终目标按任务书的“优秀完成度”验收：系统不仅可以稳定完成打卡和统计，还应具备适合投屏的班级看板、最近七天趋势、课程占比、个人与班级报告、完整模拟数据，并能在五分钟内完成连贯的现场演示。

## 2 设计约束

- 使用 HTML、CSS、原生 JavaScript、localStorage 和 ECharts。
- 系统采用纯前端方案，不要求服务器、登录系统或数据库。
- 直接打开 `index.html` 即可使用；若浏览器对本地 ES Module 有限制，运行说明提供轻量静态服务器命令作为兼容方式。
- 采用单页多视图结构，避免多页面之间重复加载和同步状态。
- 所有统计指标、排行榜、图表和报告必须来自保存的打卡记录，不使用写死的展示数字。
- 课程使用预设列表，降低同一课程因名称不同导致的统计偏差。
- 排行榜只采用正向表达，不提供倒数排名和未打卡名单。
- 不引入构建工具、前端框架、后端服务或非必要依赖。

## 3 完成范围

### 3.1 必须实现

1. 首页和全局导航。
2. 学习打卡表单及完整输入校验。
3. 本地持久化，刷新后数据仍存在。
4. 打卡记录列表、筛选、编辑和删除。
5. 个人学习统计。
6. 班级学习看板。
7. 最近七天趋势折线图、课程时长柱状图和课程占比饼图。
8. 学习之星和坚持之星排行榜。
9. 个人学习报告和班级学习报告。
10. 演示数据初始化、恢复和清空机制。
11. 空数据、错误数据和图表加载失败时的可理解反馈。
12. 响应式布局以及适合 16:9 投屏的看板布局。

### 3.2 可以延后

- 将数据导出为 JSON 或 CSV。
- 记录分页。
- 自定义课程管理。
- 深色模式。

### 3.3 明确不做

- 账号、密码、权限和在线登录。
- 云端同步和多人实时协作。
- 后端 API 和关系型数据库。
- 人工智能生成报告。
- 负面排名、惩罚机制和未打卡公开名单。

## 4 用户角色与使用场景

系统不建立账号体系，通过记录中的学生姓名区分个人。

- 学生：新增、查看、修改或删除打卡记录，查看个人统计和个人报告。
- 班委、组长或班导师：查看班级指标、课程分布、学习趋势、积极排行榜和班级报告。
- 展演者：使用预置数据演示完整链路，并现场新增一条记录证明数据会实时进入统计和图表。

## 5 信息架构与页面

应用使用单页多视图结构，顶部导航切换以下区域：

1. 首页：项目简介、今日打卡人数、本周学习总时长、累计打卡次数、热门课程和主要功能入口。
2. 学习打卡：表单、校验信息、重复记录提醒和提交反馈。
3. 记录列表：倒序记录、组合筛选、关键词搜索、编辑和删除。
4. 个人统计：学生选择器、累计时长、本周时长、打卡次数、连续天数、热门课程和个人趋势。
5. 班级看板：核心指标、三类图表和排行榜，是投屏展演的主页面。
6. 学习报告：个人报告和班级报告，可复制报告文本。

排行榜作为班级看板的一部分，不单独建立页面，以缩短导航链路并减少重复渲染。

## 6 系统架构

系统按职责划分为五层：

### 6.1 展示层

负责 HTML 结构、视图切换、表单、表格、指标卡、图表容器、对话框和通知。展示层不直接访问 localStorage，也不自行计算统计指标。

### 6.2 应用协调层

`app.js` 负责启动系统、绑定用户事件、协调数据读写以及在数据变化后触发全局刷新。新增、修改、删除、初始化和重置操作全部通过统一刷新流程更新列表、指标、图表、排行榜和报告。

### 6.3 领域逻辑层

由无界面的纯函数组成，包括记录校验、日期范围判断、汇总统计、连续打卡计算、排行榜生成和报告文本生成。此层不读取 DOM 和 localStorage，以便独立测试。

### 6.4 数据访问层

`RecordRepository` 封装 localStorage，提供加载、保存、新增、修改、删除、清空和初始化演示数据的统一接口。其他模块不能直接使用 localStorage。

### 6.5 外部可视化层

ECharts 只接收领域层整理后的图表模型。加载失败时，数字指标、记录列表和报告仍可正常使用。

## 8 数据模型

一条记录使用以下结构：

```js
{
  id: "record-uuid",
  studentName: "张三",
  date: "2026-09-15",
  course: "程序设计基础",
  durationHours: 2,
  content: "循环结构与数组练习",
  completionStatus: "completed",
  reflection: "掌握了循环嵌套",
  nextPlan: "完成数组练习",
  createdAt: "2026-09-15T10:30:00+08:00",
  updatedAt: "2026-09-15T10:30:00+08:00"
}
```

字段规则：

| 字段 | 类型 | 规则 |
|---|---|---|
| `id` | string | 唯一且不可变，用于编辑和删除 |
| `studentName` | string | 去除首尾空格后必填，长度 1 至 20 |
| `date` | string | 必填，采用本地日期 `YYYY-MM-DD`，不得晚于今天 |
| `course` | string | 必填，取自统一课程列表 |
| `durationHours` | number | 必填，大于 0 且不超过 24，最多一位小数 |
| `content` | string | 必填，长度 2 至 200 |
| `completionStatus` | enum | `completed`、`partial` 或 `not-completed` |
| `reflection` | string | 选填，最多 300 字 |
| `nextPlan` | string | 选填，最多 300 字 |
| `createdAt` | string | ISO 时间，用于稳定倒序 |
| `updatedAt` | string | ISO 时间，编辑时更新 |

localStorage 使用单一根对象：

```js
{
  version: 1,
  initializedWithDemoData: true,
  records: []
}
```

存储键固定为 `learning-dashboard:v1`。加载时发现结构错误或无法解析时，系统保留损坏值的内存副本用于控制台诊断，界面回退为空数据并提示用户恢复演示数据；系统不静默覆盖损坏数据。

## 9 模块接口

### 9.1 RecordRepository

```js
load(): StorageState
save(state: StorageState): void
list(): StudyRecord[]
add(record: StudyRecord): StudyRecord
update(id: string, changes: Partial<StudyRecord>): StudyRecord
remove(id: string): boolean
clear(): void
seed(records: StudyRecord[]): void
```

### 9.2 记录校验

```js
validateRecord(input: RecordInput, today: string): ValidationResult
findPotentialDuplicate(records: StudyRecord[], input: RecordInput): StudyRecord | null
```

潜在重复定义为姓名、日期和课程三项完全相同。重复记录不会被直接拒绝，而是要求用户二次确认，因为同一学生一天内可能针对同一课程进行多次学习。

### 9.3 统计服务

```js
buildClassSummary(records: StudyRecord[], now: Date): ClassSummary
buildStudentSummary(records: StudyRecord[], studentName: string, now: Date): StudentSummary
buildSevenDayTrend(records: StudyRecord[], now: Date): TrendPoint[]
groupDurationByCourse(records: StudyRecord[], range?: DateRange): CourseDuration[]
buildLearningStars(records: StudyRecord[], now: Date, limit?: number): RankingEntry[]
```

### 9.4 报告服务

```js
generateClassReport(summary: ClassSummary): string
generateStudentReport(summary: StudentSummary): string
```

报告是确定性的模板文本，同一统计结果必须得到同一报告。

## 10 统计口径

- 所有日期按浏览器本地时区解释，避免 UTC 转换导致日期偏移。
- 一周从周一 00:00 开始，到当前时间结束。
- 今日打卡人数：今天至少有一条记录的学生去重数。
- 本周学习总时长：本周全部有效记录的 `durationHours` 之和。
- 人均学习时长：本周总时长除以本周参与学生数；参与人数为零时显示 0。
- 累计打卡次数：有效记录总数。
- 热门课程：指定周期内累计学习时长最高的课程。
- 课程占比：课程累计时长除以全部课程累计时长；总时长为零时返回空序列。
- 最近七天趋势：包含今天在内的七个自然日，每日汇总班级学习时长；没有记录的日期补 0。
- 个人连续打卡天数：从该学生最近一个有记录的日期向前计算连续自然日；同一天多条记录只算一天。
- 学习之星：按本周累计时长降序，取前五名。
- 坚持之星：按连续打卡天数降序，取前三名。
- 排名出现相同主指标时，依次按打卡天数降序、姓名升序稳定排序。
- 展示时长统一保留一位小数，但内部计算保留数值精度。

## 11 数据流

### 11.1 启动流程

1. 读取存储状态。
2. 首次启动时写入演示数据。
3. 计算班级与个人统计模型。
4. 渲染首页、记录列表、个人统计、看板、排行榜和报告。
5. 初始化或更新 ECharts 实例。

### 11.2 数据变更流程

1. 用户提交、编辑或删除记录。
2. 标准化字段并执行校验。
3. 对新增记录检查潜在重复。
4. 通过 Repository 写入存储。
5. 重新读取完整记录集合。
6. 重新计算所有派生模型。
7. 统一刷新所有受影响视图。
8. 显示成功或失败通知。

系统不维护多份可变业务状态，localStorage 中的记录集合是持久化事实来源，界面模型均可重新计算。

## 12 交互与视觉设计

- 桌面端采用最大内容宽度和 12 列网格；班级看板在 16:9 屏幕上优先保持首屏核心信息完整。
- 首页和看板使用指标卡突出关键数字，图表区域使用清晰标题、单位和图例。
- 导航在桌面端横向显示，在小屏幕下折叠为可换行或下拉式导航。
- 表单使用清晰标签，不以占位文本代替字段名称。
- 校验错误显示在对应字段附近，并在提交后聚焦首个错误字段。
- 删除操作需要确认；恢复演示数据会覆盖现有记录，因此需要明确二次确认。
- 所有按钮、筛选器和图表必须支持常规键盘操作；颜色不能成为状态的唯一表达方式。
- ECharts 动画保持克制，优先保证投屏可读性与数据解释能力。

## 13 异常与空状态

- 必填字段为空：阻止提交并给出字段级提示。
- 时长不是数字、为零、为负数或超过 24：阻止提交。
- 日期晚于今天：阻止提交。
- 潜在重复：显示确认对话框，用户确认后才保存。
- 没有记录：指标显示 0，列表和图表显示“暂无数据”，报告说明尚无可分析记录。
- localStorage 解析失败：显示数据异常提示，提供恢复演示数据和清空数据操作。
- localStorage 写入失败或空间不足：保留当前页面输入，提示用户删除记录或导出数据，不显示成功消息。
- ECharts 未加载：图表区域显示加载失败说明，其他功能继续可用。
- 窗口尺寸变化或隐藏视图重新显示：调用图表实例的 `resize()`。

## 14 三阶段实施方案

### 阶段一 最小可运行闭环

目标是证明数据链路正确。

- 搭建项目目录、页面骨架、设计变量和导航。
- 实现数据模型、Repository 和演示数据初始化。
- 实现打卡表单、基础校验、提交反馈和记录列表。
- 实现总学习时长、累计打卡次数和课程时长汇总。
- 实现课程学习时长柱状图。
- 建立无需构建工具即可运行的浏览器测试入口。

验收：新增记录后会持久化并立即出现在列表、指标和柱状图中；刷新页面后数据仍在。

### 阶段二 标准功能闭环

目标是完成任务书要求的主要业务功能。

- 增加组合筛选、关键词搜索、编辑和删除。
- 完成个人统计和连续打卡算法。
- 完成班级看板全部核心指标。
- 完成最近七天折线图和课程占比饼图。
- 完成学习之星、坚持之星以及个人和班级报告。
- 补齐空数据、损坏数据、重复记录和图表失败处理。

验收：标准完成度所有功能可用，所有页面由同一记录集合实时驱动，统计口径测试通过。

### 阶段三 优秀展演成品

目标是提高可视质量、演示稳定性和交付完整度。

- 完成投屏与移动端响应式优化。
- 准备 30 名学生、7 天、5 门课程、至少 150 条可复现演示记录。
- 增加演示数据恢复、清空和可选导出功能。
- 完成键盘操作、焦点、文本对比度和状态表达检查。
- 完成 README、运行说明、项目说明书素材、PPT 大纲和演示流程。
- 按五分钟展演路径执行回归测试。

验收：优秀完成度所有要求满足，应用可稳定投屏，现场新增记录能实时改变列表、指标、图表、排行榜和报告。

## 15 测试策略

领域层和存储层使用浏览器原生 ES Module 测试页，不引入大型测试框架。测试覆盖：

1. 校验：空字段、非法时长、边界时长、未来日期、可选字段。
2. Repository：首次加载、增删改、刷新恢复、损坏 JSON、写入失败。
3. 统计：空集合、单条记录、多学生、多课程、跨周记录、零参与人数。
4. 七天趋势：无记录日期补零、跨月和跨年。
5. 连续打卡：同日多条、日期间断、最近日期不是今天。
6. 排行：并列主指标、稳定次级排序、少于五人。
7. 报告：空数据、典型数据和统计字段映射。
8. 手工交互：新增、重复确认、编辑、删除、筛选、导航、恢复演示数据。
9. 展演回归：刷新页面、切换视图、调整窗口大小、断开 ECharts 后备显示。

## 16 验收标准

系统只有同时满足以下条件才视为完成：

- 可以打开并清楚展示项目用途和主要功能。
- 可以新增合法打卡，拒绝非法输入，并提示潜在重复。
- 记录可以持久化、查看、筛选、编辑和删除。
- 个人统计、班级指标、排行榜和报告计算正确。
- 至少三种图表由真实或模拟打卡记录自动生成。
- 空数据、损坏存储和图表加载失败不会导致页面崩溃。
- 内置演示数据达到 30 名学生、7 天、5 门课程和至少 150 条记录。
- 看板适合 16:9 投屏，同时在常见手机宽度下可用。
- 五分钟演示流程可顺利完成：背景、功能、现场打卡、记录、看板、报告、总结。
- README 说明直接打开方式、兼容启动方式、演示数据恢复方式和主要统计口径。
